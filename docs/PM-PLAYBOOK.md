كل مهمة جديدة تبدأ من هنا، وتُراجَع عند أي تغيير في الصلاحيات أو البنية.

---

## 1. القاعدة الذهبية: التوكن لا يُقرأ ولا يُطبع

**الحقيقة التقنية المهمة:** أسرار GitHub (`Actions secrets`) هي **كتابة فقط (write-only)**.
لا توجد أي طريقة — لا عبر API ولا عبر `gh` ولا حتى بحساب Admin — لاسترجاع *قيمة* السر.
الـ API يُرجع الأسماء فقط، والقيمة تظهر حصريًا داخل بيئة تشغيل الـ Workflow.

إذن "القراءة البرمجية بلا طباعة" تُنفَّذ بالطريقة الصحيحة التالية:

```
GitHub Secret  ──(injection وقت التشغيل فقط)──►  GitHub Actions Runner  ──►  Cloudflare API
       ▲                                                                          │
       └──────────── أنا لا أرى القيمة أبدًا، ولا تظهر في أي سجل ────────────────┘
```

**الالتزامات الملزِمة:**

| # | الالتزام |
|---|----------|
| 1 | لا أطلب التوكن في المحادثة، ولا أستقبله، ولا أكتبه في أي ملف. |
| 2 | لا أُشغّل أي أمر يطبعه: ممنوع `echo $CLOUDFLARE_API_TOKEN` أو `env` أو `set -x` حوله. |
| 3 | التوكن يُستخدم فقط عبر `secrets.*` داخل `.github/workflows/`. |
| 4 | كل خطوة نشر تُغلِّف الخطأ، ولا تُصدر الـ token ضمن رسالة الفشل. |
| 5 | عند الحاجة لفحص الصلاحيات، أفحص *الاسم* فقط (`secrets.CLOUDFLARE_API_TOKEN` موجود/غير موجود) لا القيمة. |

### لماذا النشر يمرّ عبر GitHub Actions وليس من جهازي؟

بيئة العمل التي أعمل فيها معزولة شبكيًا: الوصول مسموح لـ `github.com` و`registry.npmjs.org`
و`pypi.org` فقط. `api.cloudflare.com` **محجوب** (تم التحقق منه فعليًا).
هذا ليس عيبًا — بل أفضل تصميم أمني: التوكن لا يغادر صناديق GitHub/Cloudflare أبدًا،
ولا يمرّ عبر أي بيئة وسيطة.

## 2. الأسماء المطلوبة (الأسماء فقط، والقيم عندك)

| Secret / Variable | النوع | الاستخدام |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | Secret | مصادقة wrangler للنشر |
| `CLOUDFLARE_ACCOUNT_ID` | Secret | تحديد الحساب (ليس بالغ الخطورة لكنه سرّي) |

> ⚠️ الصلاحيات الموصى بها للتوكن (Least Privilege):
> - `Account → Cloudflare Pages → Edit`
> - `Account → Workers Scripts → Edit`
> - `Account → Workers KV Storage → Edit` (إن استُخدم KV)
> - `Zone → Workers Routes → Edit` (إن رُبط نطاق مخصص)
> - `Zone → DNS → Edit` (إن أُضيف نطاق)
>
> توكن واحد بصلاحية `All zones → Edit` = مخاطرة غير مبرَّرة. الأفضل توكن لكل مشروع.

## 3. سير العمل المعياري لأي مهمة

1. **الاستلام** — أفهم الطلب، وأسأل فقط عن الغامض الذي يمنع التنفيذ.
2. **الخطة** — أكتب هيكل الملفات والخطوات قبل الكود. مهمة كبيرة = `docs/plan-<task>.md`.
3. **التنفيذ** — على فرع `arena/<id>` فقط، ثم Push، ثم Pull Request.
4. **المراجعة** — أشغّل البناء/الاختبارات محليًا قبل الطلب.
5. **النشر** — عبر `workflow_dispatch` فقط، بعد أن تُوافق/تدمج.
6. **التوثيق** — تحديث هذا الدليل و`README` عند كل تغيير معماري.

---

## 4. معايير الجودة

- **الكود**: صغير، مقروء، بلا تكرار، أسماء واضحة.
- **الأسرار**: صفر في الكود. فقط `import.meta.env` / `process.env` / `secrets.*`.
- **الألعاب**: تبدأ بـ `requestAnimationFrame` + delta time، ولا تُربط السرعة بـ FPS.
- **المنصات**: حالات تحميل/خطأ/فارغة معالَجة دائمًا.
- **الوصولية**: تباين لوني كافٍ، دعم لوحة المفاتيح، `lang="ar"` و`dir="rtl"` للمحتوى العربي.
- **الأداء**: لا مكتبة ضخمة لأجل 5 أسطر. الحجم أولًا في الويب.

## 5. البيئات وإدارة الأسرار

| البيئة | المصدر | متى |
|---|---|---|
| `preview` | Wrangler/Pages preview | كل PR |
| `production` | دفع إلى `main` أو إطلاق يدوي | بعد المراجعة |

التوكنات تُفصل بيئيًا: توكن المعاينة يمكن أن يكون محدودًا بفرع/نطاق،
وتوكن الإنتاج لا يُشارك معه.

---

## 6. ممنوعات مطلقة

- ❌ طباعة أي سر، حتى جزئيًا، أو في لقطة شاشة، أو داخل تعليق PR.
- ❌ كتابة سر في `.env` ثم الـ commit (نتحقق من `.gitignore` دائمًا).
- ❌ تشغيل `wrangler login` أو تخزين `~/.wrangler` بصلاحيات دائمة.
- ❌ التجربة مباشرة على الإنتاج: التجربة على preview أولًا.
- ❌ الدفع إلى `main` مباشرة دون مراجعة (إلا إن طلبتَ ذلك صراحة).
